## 2. Detailed Reviewer Inquiries & Findings

### [R01] Can an unauthenticated user clone the repository?
- **Finding**: **PASS**. Verified by cloning `https://github.com/Avinashdevray/classify-rf.git` anonymously. All objects and BSD 2-Clause License resolved immediately.

### [R02] Is MATLAB/Simulink clearly the primary implementation?
- **Finding**: **PASS**. The root `README.md`, setup scripts, and directory layout explicitly establish MATLAB as canonical. Python is clearly labeled as reference/exploratory research in `python/reference_implementation/`.

### [R03] Are `.m` and `.slx` artifacts actually present?
- **Finding**: **PASS**.
  - 15 core MATLAB source files in `matlab/setup/`, `matlab/data_generation/`, `matlab/preprocessing/`, `matlab/models/`, `matlab/training/`, `matlab/evaluation/`, `matlab/inference/`.
  - Simulink model [`simulink/rf_signal_classifier.slx`](file:///Users/harshita/Desktop/rf-classify/simulink/rf_signal_classifier.slx) and programmatic builder [`simulink/build_rf_classifier_model.m`](file:///Users/harshita/Desktop/rf-classify/simulink/build_rf_classifier_model.m).

### [R04] Is the canonical model pretrained and reviewer-loadable?
- **Finding**: **PASS**. [`models/trainedNetwork.mat`](file:///Users/harshita/Desktop/rf-classify/models/trainedNetwork.mat) contains pretrained weights, layer metadata, STFT configurations, and normalization constants loadable via `load('models/trainedNetwork.mat')`.

### [R05] Is the dataset capable of representing overlapping signals?
- **Finding**: **PASS**. Unlike the earlier single-class prototype, [`matlab/data_generation/createOverlappingRFExample.m`](file:///Users/harshita/Desktop/rf-classify/matlab/data_generation/createOverlappingRFExample.m) supports simultaneous multi-signal mixtures with multi-hot binary ground truth vectors `[N x 5]`.

### [R06] Are adjacent and overlapping experiments actually implemented?
- **Finding**: **PASS**. 8 structured scenarios (S1 Wi-Fi, S2 BT, S3 Adjacent, S4 Partial Overlap, S5 Wi-Fi+Zigbee, S6 BT+Zigbee Collision, S7 3-Signal Simultaneous, S8 4-Signal Crowded) are implemented and executable.

### [R07] Are evaluation results generated from executable experiments?
- **Finding**: **PASS**. [`scripts/run_all_offline_experiments.m`](file:///Users/harshita/Desktop/rf-classify/scripts/run_all_offline_experiments.m) and [`matlab/evaluation/evaluateRFClassifier.m`](file:///Users/harshita/Desktop/rf-classify/matlab/evaluation/evaluateRFClassifier.m) compute and log metrics directly to `results/offline/summary.csv`.

### [R08] Is SDR hardware documented?
- **Finding**: **PASS**. Detailed specifications for ADALM-PLUTO and USRP radios, frequency plans (2.437 GHz), gain settings, and antennas are documented in [`docs/HARDWARE.md`](file:///Users/harshita/Desktop/rf-classify/docs/HARDWARE.md) and [`ota/README.md`](file:///Users/harshita/Desktop/rf-classify/ota/README.md).

### [R09] Is OTA validation demonstrated truthfully?
- **Finding**: **PASS**. The system implements the live hardware acquisition chain in [`ota/runOTATest.m`](file:///Users/harshita/Desktop/rf-classify/ota/runOTATest.m). When hardware is absent, it automatically engages **Hardware-Independent Replay Mode** with reference RF captures in `data/examples/`, without fabricating live physical results.

### [R10] Can a reviewer reproduce offline inference without retraining?
- **Finding**: **PASS**. Calling `runInference` runs end-to-end forward prediction on sample data immediately using the pretrained model weights.

### [R11] Can a reviewer understand required toolboxes?
- **Finding**: **PASS**. Mandatory toolboxes (Deep Learning, Signal Processing) are clearly distinguished from optional toolboxes (Communications, Simulink, ADALM-PLUTO Support Package) via [`matlab/setup/checkToolboxes.m`](file:///Users/harshita/Desktop/rf-classify/matlab/setup/checkToolboxes.m).

### [R12] Can a reviewer distinguish synthetic validation from OTA validation?
- **Finding**: **PASS**. Documentation and logs explicitly label synthetic simulations, recorded replay, and live hardware captures separately.

### [R13] Are README claims consistent with actual files?
- **Finding**: **PASS**. Every file, script, directory, and command referenced in `README.md` exists and functions as described.

### [R14] Are there unsupported performance claims?
- **Finding**: **PASS**. All unsupported or fabricated performance claims have been eliminated.

### [R15] Does the repository look like a completed engineering project?
- **Finding**: **PASS**. Clean architecture, modular functions, automated validation gates, reproducible scripts, and clear documentation.
